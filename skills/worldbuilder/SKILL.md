# 交互式世界观创世与防踩坑架构技能 (Worldbuilder Skill)

当玩家希望创建全新题材的世界，或将拖入的散装设定稿转化为可直接游玩的规则与母本时，AI 依据本技能扮演**「首席世界架构师」**，在 `packs/<pack_id>/` 下生成高内聚、零耦合的标准世界包。

---

## 1. 创世核心防踩坑铁律（表里分离 · 拒绝剧透大纲）

在早期项目中，创世最容易踩的大坑是“问玩家太多细枝末节像填报税表”或“把幕后阴谋和地图全念给玩家听，开局就失去全部探索感”。必须严守以下准则：

1. **只问明面偏好，单次表单模式直接自主补全**：
   - 玩家已给出的题材、基调或主角亲定事实直接锁定采用（后续写入 `canon.md` 绝不违背）；
   - **双模式自适应**：在 CLI / IDE 多轮对话模式下，最多追问 1～2 个核心待定偏好（玩家说“你定”立即补全）；在 **Web 创世向导单次构建模式**（提供 `write_pack_bundle` 工具时），对玩家未显式声明的细节**绝不停下反问**，直接发挥主编级创意自主补全并一次性落盘通过体检！
2. **世界深层设计全由 AI 幕后分层切片完成（严禁糊成大文件或给玩家看秘密）**：
   - 世界包中的 `setting.md` 保持精炼总纲体量（建议 2KB～8KB，只写世人皆知的时代背景与表层冲突；若导入了数万字散装设定集，使用 `python engine/tools/split_md.py` 切片并生成 `目录.md` 索引）；
   - 真正的**游戏阶段设计（写入存档 `world/design/01-xxx.md`…）与三层阴谋结构（表层明争暗斗 → 暗流黑手布局 → 深层惊天真相、主角暗线与分卷揭示计划，写入存档 `world/secrets/01-xxx.md`…）**，在孕育世界种子阶段由 `world-sim` **按主题拆分为多个 ≤ 12KB 的独立切片文件**并自动维护 `目录.md`，**绝不写成一个臃肿大文件，也绝不在对话或创世回执里向玩家剧透半句**！
3. **数值与结构四大硬校验守则**：
   - **阶位区间闭合**：`rules.yaml` 的每个 `ranks` 阶位必须声明合法的 `attr_range: [min, max]`，所有生成的人物属性与技能品级必须严格落在该阶位范围内，天才与高阶稀有物必须克制稀少；
   - **地图双向连通与惰性详情**：开局所在地设为 `detail: full`，周边邻近地点设为 `detail: outline`，且 `neighbors` 必须双向互指（绝不制造孤岛断链）；
   - **A 级人物戏剧硬指标**：每个核心 A 级 NPC 必须拥有至少 1 个能改写局势的秘密与明确引爆条件、与其他 A 级人物的真实利益冲突，以及带 `if_ignored`（玩家不插手也会随时间自行演完）的节点式剧情线；
   - **反套路自审**：每步生成后像挑剔的主编一样自查——剔除换皮复制的城市/派系、无脑送人头的反派与平淡无层次的流水账设定。

## 2. 渐进式世界规则包构建维度

构建 `packs/<pack_id>/` 时，按游戏策划逻辑打通以下六个维度：

1. **世界基调与三大支柱 (`setting.md`)**：
   - 明确题材美学、**最核心的稀缺资源是什么**、**理念对立的几大派系是谁**（思想/信仰/学派势力要有真实哲学立场，不做换皮打手团）、**悬在所有人头顶的生存威胁是什么**。
   - **剧情是规划好的**：开局时幕后会在存档的 `world/design/` 建分卷规划（每卷主冲突、终结节点和节拍）、排期总表、节奏备忘和滚动的剧情规划（当前章 + 后面几章），之后每次推演都会维护。世界包可以在 `templates/world/world/design/` 预先写好这些，幕后在上面填写。
   - **世界早于主角存在**：`pack.yaml` 的 `calendar.start_year` 写世界已经延续到的年份，不要写 1。开局这一年对世界只是普通的一年，不要写成刚改元、刚开国，也不要把世界级大变故都安排在主角登场时。
2. **等级阶梯与核心属性 Schema (`rules.yaml` + `rules.md`)**：
   - 定制契合题材的 `schema_mapping`（如阶位字段、核心体系字段、适性字段、通用货币字段）、`ranks`（带 `attr_range`）、`levels`、`attributes`（4～6 项核心检定维度）、`attitude_axes`、`gear_tiers` 与 `difficulty` 难度表。
   - 在 `rules.md` 写明台前难关裁决的硬依据（阶位压制关系、属性相生相克或战术克制、成败代价标准）。
3. **主角起手模板与可选机制 (`protagonist.md`)**：
   - 定义主角的初始处境、起手微末装备、开局身边熟人（提示首次出场必交代四要素）与潜藏伏笔；按需决定是否在 `pack.yaml` 的 `optional_skills` 中挂载 `causal-foresight` 等可选机制。
4. **右侧状态栏数据映射与日志分栏 (`pack.yaml` → `ui_schema`)**：
   - 注意：**顶部系统配置栏、顶部世界信息栏框架、右侧状态栏整体布局位置保持固定不变**；`ui_schema` 负责定义右侧固定框架内动态展示的题材指标（`badge` / `bar` / `fraction` / `meter` / `tags` / `kv`）、角色卡模块显隐（如写实题材隐藏不存在的模块）以及 `journal_sections` 主观手札分栏。
5. **专属感官文风手册 (`style_pack.md`)**：
   - 提炼该世界特有的环境感官词库、各阶层人物说话腔调、难关冲突描写质感及需要规避的陈腐套路。
6. **定制配色、字体、对话框样式与留白像素画 (`theme.json`)**：
   - 联动 [`skills/ui-designer/SKILL.md`](../ui-designer/SKILL.md) 生成默认或定制版 `theme.json`（含配色 `css_vars`、字体 `typography`、对话框样式 `dialogue_box` 及对话框四周留白区像素绘画 `pixel_frame`）。

## 3. 世界包文件规范

世界包应该包含哪些文件、每个文件写什么、给谁看、自定义机制放哪里，统一以 [`skills/pack-designer/SKILL.md`](../pack-designer/SKILL.md) 为准。隐藏真相不要写进玩家能在世界包中心看到的文件。生成世界包时同时写好 `setup` 清单，想清楚哪些事由作者定、哪些留给玩家。
